GFriend AI Agent

Technology Stack Overview

The GFriend AI Agent uses a modern, fully local technology stack that runs entirely on Windows development systems with zero cloud dependencies. This architecture ensures data security, zero ongoing costs, and high-quality code generation specifically trained for the GFriend automation framework.

Key Principle: 100% local execution — no API keys, no cloud services, no data transmission. All components run on your Windows machine.

🧠 1. Language Model Layer

Qwen2.5-Coder-7B-Instruct

Attribute Value
Type Open-source Large Language Model specialized for code generation
Parameters 7 billion (7B)
Quantization Q4_K_M (4-bit quantization)
Model Size ~4.5 GB on disk
RAM Required 8-12 GB during inference
Context Window 32,768 tokens (~25,000 words)
License Apache 2.0 (fully open source)

Why This Model?

  • ✅ Quality: Rivals GPT-3.5 on code generation benchmarks
  • ✅ Cost: Free and open-source (no per-use fees)
  • ✅ Privacy: Runs entirely offline after download
  • ✅ Size: 7B is the sweet spot — good quality, runs on consumer hardware
  • ✅ Specialization: "Coder" variant optimized for programming tasks

Model Strengths

  • State-of-the-art code understanding and generation
  • Trained on diverse programming languages (C#, JavaScript, Python, etc.)
  • Excellent at following structured instructions
  • Long context support (can process full test case descriptions with examples)
  • Deterministic outputs when temperature is low (0.1) — same input produces same output

Quantization Explained

Format Size Quality Use Case
FP16 (Original) ~28 GB 100% Research/Training
Q8 (8-bit) ~7.5 GB 99.5% High-end servers
Q4_K_M (4-bit) ~4.5 GB 97% Desktop machines (our choice)
Q3 (3-bit) ~3.5 GB 93% Low-end devices
Result: We achieve 97% of original quality with 85% size reduction, making the model practical for Windows development machines.

LM Studio

LM Studio is a desktop application for running local LLMs with an OpenAI-compatible API server.

Key Features

  • ✅ Native Windows application (no WSL required)

  • ✅ GPU acceleration (CUDA for NVIDIA, DirectML for AMD/Intel)
  • ✅ CPU-only fallback support
  • ✅ Built-in API server (OpenAI-compatible REST API)

  • ✅ Temperature and token control via UI

API Endpoint

http://localhost:1234/v1

Python Integration Example

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:1234/v1",
    api_key="not-needed"  # LM Studio doesn't require auth for local
)

response = client.chat.completions.create(
    model="qwen2.5-coder-7b-instruct",
    messages=[
        {"role": "system", "content": "You generate GFriend automation scripts."},
        {"role": "user", "content": "Convert this test case: ..."}
    ],
    temperature=0.1,      # Low = deterministic
    max_tokens=2048       # Max output length
)

script = response.choices[0].message.content

🗄️ 3. Vector Database Layer

ChromaDB

ChromaDB is an embedding database that enables semantic search over the GFriend knowledge base.

Technical Specifications

Attribute Value
Storage Backend SQLite (persistent local files)
Embedding Dimensions 768
Search Algorithm Cosine similarity (HNSW index)
Storage Size ~20-30 MB (keywords + scripts + docs)

ChromaDB Structure

ChromaDB Root Directory (./chroma_db/) ├── chroma.sqlite3 (metadata + indices) ├── collections/ │ ├── gfriend_keywords/ (26 GFK.* libraries) │ │ └── ~1,300 keyword definitions │ ├── sample_scripts/ (validated scripts) │ │ └── ~20+ complete GFriend scripts │ ├── kt_docs/ (GFriend documentation) │ │ └── Core concepts, conventions, examples │ └── variable_files/ (config templates) │ └── Device configs, test data structures

How It Works

Phase 1: Ingestion (One-Time Setup)
# 1. Document is split into chunks
chunk = "GFK.Web.Open With Chrome(url): Opens Chrome browser and navigates to the specified URL"

# 2. Embedded into 768-dimensional vector space
embedding = embedding_model.embed(chunk)
# Result: [0.123, -0.456, 0.789, ..., 0.234]  (768 numbers)

# 3. Stored with metadata
collection.add(
    documents=[chunk],
    embeddings=[embedding],
    metadatas=[{
        "library": "Web",
        "keyword": "Open With Chrome",
        "category": "browser_control"
    }],
    ids=["web_open_chrome_001"]
)
Phase 2: Retrieval (Runtime)
# User's test step: "Open browser and navigate to login page"
query = "open browser and navigate to login page"
query_embedding = embedding_model.embed(query)

# Semantic search using cosine similarity
results = collection.query(
    query_embeddings=[query_embedding],
    n_results=5,
    where={"library": "Web"}  # Optional filter
)

# Returns most similar keywords:
# 1. GFK.Web.Open With Chrome (similarity: 0.92)
# 2. GFK.Web.Navigate To (similarity: 0.87)
# 3. GFK.Web.Go To URL (similarity: 0.85)
# 4. GFK.Web.Wait For Page Load (similarity: 0.78)
# 5. GFK.Web.Check Page Title (similarity: 0.72)

🔤 4. Embedding Model

nomic-embed-text-v1.5

A sentence transformer model that converts text into semantic vectors for similarity search.

Attribute Value
Model Type Sentence Transformer (BERT-based)
Dimensions 768
Context Length 8,192 tokens (~6,000 words)
Model Size ~550 MB
Performance ~500 embeddings/second (CPU)
License Apache 2.0 (fully open)

How Embeddings Work

# Input text
text = "Click the Login button on the web page"

# Output: 768-dimensional vector
embedding = [0.123, -0.456, 0.789, ..., 0.234]

# Similar sentences have similar vectors (measured by cosine similarity)
similarity("Click the Login button", "Press the Sign In button") = 0.89
similarity("Click the Login button", "Print the document") = 0.21

Why This Embedding Model?

🔗 5. RAG Framework

LangChain

LangChain is a framework for building applications with Large Language Models, providing abstractions for RAG (Retrieval-Augmented Generation) pipelines.

Core Components Used

from langchain.embeddings import HuggingFaceEmbeddings
from langchain.vectorstores import Chroma
from langchain.chat_models import ChatOpenAI
from langchain.chains import RetrievalQA

# 1. Embedding function
embeddings = HuggingFaceEmbeddings(
    model_name="nomic-ai/nomic-embed-text-v1.5"
)

# 2. Vector store connection
vectordb = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings,
    collection_name="gfriend_keywords"
)

# 3. LLM connection (LM Studio)
llm = ChatOpenAI(
    base_url="http://localhost:1234/v1",
    api_key="not-needed",
    temperature=0.1,
    max_tokens=2048
)

# 4. RAG chain (retrieval + generation)
qa_chain = RetrievalQA.from_chain_type(
    llm=llm,
    retriever=vectordb.as_retriever(search_kwargs={"k": 5}),
    return_source_documents=True
)

What LangChain Does for Us

  • Abstraction: Hides complexity of connecting embeddings, vector DB, and LLM
  • Compatibility: Works with 100+ LLMs and vector databases
  • Production-ready: Battle-tested by thousands of companies
  • Extensible: Easy to add custom retrievers, parsers, validators
  • Community: Largest LLM framework ecosystem (active development)

RAG Pipeline Flow

1. User Query: "Generate script for test case TC-001" ↓ 2. Retrieve Context from ChromaDB: • Top 5 relevant GFK.* keywords • Top 3 similar scripts • GFriend conventions document ↓ 3. Build Prompt: [System] You are a GFriend script generator... [Context] Relevant keywords: GFK.Web.Open With Chrome, ... [Context] Similar script example: ... [User] Generate script for: TC-001 - Login Test ↓ 4. LLM Generates Script: using Web Login Test { Web.Open With Chrome(${URL}) ... } ↓ 5. Return Script + Source Documents (for validation)

📊 7. Data Processing Layer

pandas + openpyxl

pandas — Data Analysis Library

Industry-standard library for working with tabular data (Excel, CSV)

Excel Parsing Pipeline

import pandas as pd

# 1. Load Excel file
df = pd.read_excel("testcases.xlsx", sheet_name="Test Cases")

# 2. Normalize column names
df.columns = df.columns.str.strip().str.lower().str.replace(" ", "_")

# 3. Detect format (TestRail vs. Custom Template)
if "tc_id" in df.columns:
    format_type = "custom"
elif "id" in df.columns and "title" in df.columns:
    format_type = "testrail"

# 4. Group by TC_ID (for multi-row test cases)
for tc_id, group in df.groupby("tc_id"):
    # Each group = one test case with multiple step rows
    steps = []
    for _, row in group.iterrows():
        steps.append({
            "step_number": row["step_number"],
            "action": row["step_action"],
            "expected": row["step_expected_result"]
        })
    
    tc = NormalizedTC(
        tc_id=tc_id,
        tc_title=group.iloc[0]["tc_title"],
        steps=steps
    )

Why pandas?

  • Industry standard: Most widely used Python data library
  • Excel/CSV support: Built-in readers for both formats
  • Powerful grouping: Essential for multi-row test case format
  • Memory efficient: Can handle 1,000+ test cases without issues
  • Data validation: Easy filtering, null checking, type conversion

Type-Safe Configuration with Pydantic

from pydantic import BaseModel, Field
from typing import List, Optional

class TestStep(BaseModel):
    step_number: int
    action: str
    expected_result: str
    library_hint: Optional[str] = None

class NormalizedTC(BaseModel):
    tc_id: str
    tc_title: str
    domain: Optional[str] = None
    steps: List[TestStep]
    preconditions: Optional[str] = None
    
    class Config:
        validate_assignment = True  # Validate on attribute assignment

Benefits of Pydantic

  • Runtime validation: Catches bad Excel data early
  • Auto-generated docs: Types become documentation
  • IDE support: Full autocomplete for all fields
  • Type safety: Prevents bugs without mypy overhead
